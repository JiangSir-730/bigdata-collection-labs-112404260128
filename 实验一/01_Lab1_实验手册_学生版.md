# 实验一：静态页面与 API 数据采集

**学时：4 学时**  
**平台：SmartPark DataLab**  
**代码文件：`lab1_html_api.ipynb`**

## 1. 实验目标

本实验完成两类典型 Web 数据采集：

```text
Device：动态加载 → 找到 API → JSON → 分页采集全部设备
Company：静态加载 → HTML → BeautifulSoup → “下一页” → 采集 3 页
```

完成实验后，应能够：

1. 判断网页数据是静态加载还是动态加载；
2. 使用 Network 找到动态页面对应的 API；
3. 使用 `requests` 采集 JSON API 并处理分页；
4. 使用 BeautifulSoup 和 CSS Selector 解析静态 HTML；
5. 根据“下一页”链接连续采集多页数据；
6. 检查采集数量、ID 唯一性和跨数据源一致性；
7. 将验证后的数据保存为本地文件。

# 2. 先判断：静态加载还是动态加载

本课程采用一个很直接的判断方法。

## 2.1 查看网页源代码

在浏览器页面中：

```text
右键 → 查看网页源代码
```

然后按 `Ctrl + F`，搜索页面上已经看到的一条目标数据，例如：

```text

```

### 情况 A：源代码中能找到目标数据

说明这些数据已经随 HTML 一起返回，可以按**静态页面**处理：

```text
requests → r.text → BeautifulSoup → CSS Selector
```

### 情况 B：页面上能看到数据，但源代码中找不到

说明数据不是随初始 HTML 一起返回。本实验中的这类页面通过 **API** 动态加载数据。

继续打开：

```text
F12 → Network → Fetch/XHR
```

刷新页面，找到返回目标数据的请求。

打开：

```python
from bs4 import BeautifulSoup

base_url = "https://115.159.159.82"

r = requests.get(current_url, timeout=10)
soup = BeautifulSoup(r.text, "html.parser")
```

---

## 4.1 设计企业记录的 CSS Selector

先在 Elements 中找到**一条完整企业记录的最外层节点**。

设计 Selector 时，按下面顺序考虑：

```text
① 有没有语义明确且稳定的 id？
↓
② 有没有稳定、唯一或足够明确的 class？
↓
③ 有没有 data-* 属性？
↓
④ 能不能通过父子层级定位？
↓
⑤ 最后才考虑复杂位置关系
```

原则：

> **Selector 不是越长越好。优先选择短、语义明确、对页面结构变化不敏感的写法。**

浏览器 **Copy selector** 可以作为参考，但如果得到很长的 `nth-child(...)` 路径，应再观察 DOM，尝试写得更简洁。

如果使用 AI 辅助分析，可以把目标节点的一小段 `outerHTML` 提供给 AI，让它给出“尽量短、稳定”的 selector；最终仍要在代码中验证：

```python
cards = soup.select("填写你设计的企业记录 selector")

print("本页企业数：", len(cards))
```

第 1 页应得到：

```text
20 条企业记录
```

---

## 4.2 提取企业字段

每条企业记录至少保留：

```text
company_id
name
industry
zone
device_count
status
```

建议先解析第一条：

```python
card = cards[0]
```

行业、区域、设备数量等信息采用 `dt/dd` 结构，可以先转换成字典：

```python
details = {}

for item in card.select("dl > div"):
    key = item.select_one("dt").get_text(strip=True)
    value = item.select_one("dd").get_text(strip=True)
    details[key] = value

print(details)
```

然后根据实际 DOM 提取其他字段。

注意：

- `company_id` 可以关注 HTML 中的 `data-*` 属性；
- `name`、`status` 等字段在当前记录内部定位即可；
- `device_count` 最终转换为整数；
- **先定位一条记录，再在记录内部提取字段。**

完成第一页循环后：

```python
print("本页企业数：", len(companies))
```

应得到：

```text
20
```

# 5. 任务三：根据“下一页”连续采集 3 页 Company

在 Elements 中找到页面底部的“下一页”链接。

观察：

```text
它是什么标签？
有哪些 class / 属性？
href 是什么？
```

设计一个稳定的 selector，并验证：

```python
next_link = soup.select_one("填写你设计的下一页 selector")

print(next_link.get_text(" ", strip=True))
print(next_link.get("href"))
```

如果 `href` 是相对路径：

```python
from urllib.parse import urljoin

next_url = urljoin(current_url, next_link.get("href"))
print(next_url)
```

把下面三个步骤组合到循环中：

```text
请求当前页
→ 解析本页企业
→ 找到下一页 href
```

连续采集 **3 页**。

目标：

```text
第1页：20条
第2页：20条
第3页：20条
Company 总数：60
```

# 6. 任务四：验证采集结果

## 6.1 数量与 ID 唯一性

```python
print("companies:", len(companies))
print(
    "unique company_id:",
    len(set(x["company_id"] for x in companies))
)

print("devices:", len(devices))
print(
    "unique device_id:",
    len(set(x["device_id"] for x in devices))
)
```

目标：

```text
Company：60 条，60 个唯一 company_id
Device ：5000 条，5000 个唯一 device_id
```

## 6.2 Company–Device 一致性

根据全部 Device 的 `company_id` 统计每家企业实际设备数：

```python
from collections import Counter

device_counts = Counter(
    x["company_id"] for x in devices
)
```

再与前 60 家 Company 页面中的 `device_count` 比较。

正常教学数据场景下：

```text
不一致企业数 = 0
```

# 7. 任务五：保存采集结果

数据验证通过后，将结果保存下来。

建议在 Notebook 同级目录建立：

```text
data/
```

保存为 JSON：

```python
from pathlib import Path
import json

data_dir = Path("data")
data_dir.mkdir(exist_ok=True)

with open(data_dir / "devices.json", "w", encoding="utf-8") as f:
    json.dump(devices, f, ensure_ascii=False, indent=2)

with open(data_dir / "companies.json", "w", encoding="utf-8") as f:
    json.dump(companies, f, ensure_ascii=False, indent=2)

print("数据已保存到 data/ 目录")
```

检查：

```text
data/devices.json
data/companies.json
```

本实验先使用 JSON 保存，不引入 Pandas、数据库或 Parquet；这些内容将在后续实验中继续学习。
